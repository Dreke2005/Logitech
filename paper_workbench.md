# PaperBridge

Start the workbench from the project directory.

    uv run paper_workbench.py

Press **Ctrl+Alt+F9** to switch between PaperBridge and the virtual keyboard,
touchpad, gaze, and lip-reading tools. In the integrated workspace, the MX Keypad
webcam key switches directly to PaperBridge. See the [workspace guide](README.md#switch-between-camera-tools).

Choose an app icon on page 1 and press the key for what you're about to write, such as **Code**, **Plot**, **Equation**, or **Schematic**. That starts the camera if needed and captures a reference frame. **Camera** turns the stream on or off. The green box shows the detected paper or the writing area you selected by dragging. Yellow lines show hand motion, the magenta crosshair marks a visible nib supported by edges inside the capture area, and blue lines show pen-down strokes. If PaperBridge cannot locate the writing area at the end of a recording, it asks for a still or manual selection. Pass `--debug-capture` to save full-frame diagnostics and replay files for troubleshooting.

To finish, draw a small closed circle after the text, apart from it and a bit larger than your letters, and hold still briefly. The orange ring confirms it, and generation starts without a key press. The circle itself is not transcribed. For **Diagram** and **Copy** a circle is part of the content, so finish those by moving your hand away or pressing the key again. That also works for every other key.

Reading starts from the ink itself, on both paths. While you write, PaperBridge registers every thin, dark mark that appears on the paper since the key press, wherever your hand isn't covering it at that moment. Over the recording each stroke is uncovered at some point, so the record ends up with the complete writing even if your hand still rests on the page; only the last letters under the pen need you to lift your hand. For a snapshot (two quick presses, or a still), the same kind of picture is lifted out of the photo: marks that are darker than the paper around them and as thin as a pen stroke, without paper texture, shadows, the desk, or the page edge. Either way the reader gets a clean picture of just the ink, dark on white, upright, and scaled to about 64 px per line of text.

Text, equations, code, tables, plans, and commit or branch names are read by a small OCR model in the mode the key calls for (formula, table, or text). It answers in plain text in a fraction of a second. The key's validator then checks the reading: an equation must parse, code must be balanced, table rows must have the same number of cells. A rejected equation first gets a look-alike repair (a handwritten t and + are the same two strokes; the swap is accepted only when exactly one makes the equation valid), then a second look in the other mode. Drawings whose meaning is in boxes, arrows, and symbols (circuits, branch diagrams, flowcharts) go to the vision model instead, which takes several seconds.

Most results need no model after the reading. A checked equation becomes display math, a function in the selected language, or a MATLAB function handle directly; writing that already is valid code is kept as it is; a class sketch becomes one source file per class plus an entry file; a report outline becomes its skeleton; functions of x become a plotting program; a table, a plan, and git actions are computed. Only pseudocode, free-form project ideas, and plots that are more than functions of x are handed to a language model.

That is how PaperBridge works on its own computer, with the local models. By default the cloud does the work instead, with Claude, through the Claude Code CLI you are signed in to on this computer. For **Code**, **Plot**, and **Equation**, one request per key press reads the photo of your writing, says what it is, and writes the result for the app you are in: about three to six seconds from the key press to the file, where the local models need twenty or more for anything they cannot convert directly. Claude also copes much better with small, faint handwriting than the local reader. The check window shows the reading and, under it, one line about what will be made; if you correct the reading, the result is made again from your text. The result is checked before it opens (Python must compile, a plot program must run), and a failed check goes back once for a fix. The other keys are read by Claude and converted as described above; circuits are read, built, and tried in LTspice in the same way. The local models take over by themselves when Claude is not installed, the computer is offline, or an answer takes too long, and for the readings shown while you still write. The status line ends with what was used, such as `[read and generated in one cloud request (Claude) in 2.6 s]` or `[generated by the local model in 22.0 s]`. See [Cloud or local](#cloud-or-local) to switch and for what is sent.

The pen-tip track is corrected from the ink as well: the tip landmark estimated from your hand usually sits several pixels off the nib, so the samples of the last seconds are shifted onto the ink that appeared, and that shift is applied to the samples to come. While you write, the ink so far is read in the background whenever the pen pauses and shown as a pop-up; if you finish without adding more, that reading is used directly. The status line shows which source was read: the ink, the pen trace, or the photo.

Frames and traces stay in memory. **Capture page** freezes a frame for manual selection and a one-press conversion. **Resume live** returns to the camera. Pressing **Camera** again stops the stream.

## Work without looking at the workbench

You don't need the workbench window. Started from the keypad, it stays minimized.

- **One key press.** An action key starts the camera when needed, records, reads, generates, and opens the result in the app: VS Code, MATLAB, LTspice, or the browser.
- **Two quick presses for what is already written.** Press the same action key twice within about a second and PaperBridge takes a snapshot instead of recording: it reads what is already on the page and generates the code, project, equation, table, or plan from that. A dashed oval or a dragged selection limits it to one part of the page.
- **Status on the key.** The key you pressed shows a bar along its bottom edge: red while recording, amber while reading and generating, green when done, and red at top and bottom when it failed.
- **Pop-up results.** While the window is minimized or in the background, each status message appears for a few seconds at the bottom right of the screen.
- **Folders are asked once.** The Git repository, the LaTeX project, and the VS Code language are remembered in `%LOCALAPPDATA%\LogiInsightPaper\settings.json`. Use **Browse** on the version-control page to change the folder.
- **Context from your project.** The reader is told what the pressed key expects, and also gets names from the selected project: functions, classes, and variables for code, macros and labels for LaTeX, and branch names for Git. That narrows what an unclear word can be.
- **Inline AI gets the handwriting.** A generated code file starts with your transcription as a comment, so Copilot or another inline assistant in the editor continues from what you wrote.
- **Math is checked.** For equations, each step of a derivation is checked with sympy, and the first step that doesn't follow is named in the notes and the pop-up. A line ending in `= ?` gets its result. A definition such as `y = x^2 + 1` is left alone.

## Copy and paste between apps

To copy something on paper, draw a **dashed oval** around it, with short gaps and space between the oval and the writing. Lift your hand and press **Copy**. If the oval is missed, freeze the page and drag around it. Copy also takes the current draft, or the text selected in it. PaperBridge records *what* it copied (equation, code, table, plot, diagram, todo, or text) in `%LOCALAPPDATA%\LogiInsightPaper\clipboard.json`, with the source app and any rendered figure. The plain text also goes to the Windows clipboard. A copied plot is rendered right away.

Open another app's page and press **Paste**. The result depends on what was copied and where you paste it. Generated files open in the target app, and the status line names the copied kind and what Paste made of it. Paste uses this typed copy only while the Windows clipboard still holds the copied text. Anything you copy elsewhere afterward is pasted as before.

| Copied | LaTeX | VS Code | MATLAB | ChatGPT | Git |
| --- | --- | --- | --- | --- | --- |
| Equation | `equation` environment file plus `\input` | Function in the selected language | Anonymous function plus `fplot` script | Explain-and-check prompt | Commit message |
| Code | `lstlisting` file | New file in the open project, or a draft | `.m` file | Review prompt | Commit message |
| Table | Booktabs table in `tables/` | CSV file | `table()` or `array2table` script | Explain prompt | — |
| Plot | The equation or code it was made from, then the figure, inserted in the text; the file goes to `figures/` | Matplotlib script | Plot script | Explain prompt | — |
| Diagram | Figure if rendered, otherwise `verbatim` | Markdown note | Comments | Explain prompt | Runs it as a [diagram](#draw-a-branch-diagram) |
| Todo | `itemize` list | TODO comments | TODO comments | Planning prompt | Adds the open items to `TODO.md` and commits only that file |
| Text | Paragraph | Markdown note | Comments | Review prompt | Commit message for current changes |

In LaTeX, fragments go into the project chosen with **Browse**. PaperBridge adds the `\input` line before `\end{document}` of `main.tex` or the only complete document, and loads `booktabs` or `listings` there if needed. Without a clear root file, the `\input` line goes to the clipboard. Without a project, Paste asks for one and saves a standalone draft if you cancel. ChatGPT pastes are staged in the workbench; press **ChatGPT** to copy the prompt and open the chat.

### Tables

On the LaTeX page, press **Table** and draw a grid. Separate the columns with vertical lines and write one row per line. A first row of labels becomes the header. PaperBridge escapes LaTeX special characters and right-aligns numeric columns. It saves a booktabs `tabular` in a `table` float as `tables/table_<n>.tex` in the selected project, with `\input` and `\usepackage{booktabs}` added as for equations. It then opens the root file. Without a selected project, it opens a standalone draft instead.

## Transfer a graph or code

Generated working files are saved under `%LOCALAPPDATA%\LogiInsightPaper\drafts`.

1. In MATLAB or VS Code, start the camera, press **Plot**, then write the function, such as `y = x^3 + e^x`. Up to four functions, one per line, are drawn together, and a line such as `-2 <= x <= 2` sets the range (−5 through 5 otherwise). If the equation is already on paper, use **Capture page** and select it before pressing **Plot**. You can also use the **Paste** key to stage an equation copied from an editor. The result is a program, not just a picture:
   - **VS Code**: `paper_plot.py` (matplotlib) is written, run, and opened in VS Code together with the figure it saved, `paper_plot.png`. It takes about a second after the reading. Change the program and run it again to redraw. The program is Python whichever language is selected.
   - **MATLAB**: `paper_plot.m` is written and opened in MATLAB. A MATLAB that has to be started runs it right away; in a MATLAB that is already open, press F5. Starting MATLAB takes most of a minute, so the workbench doesn't wait for it: its preview is drawn from the same expression.
   - A plot that is more than functions of x, such as *sin x and cos x from 0 to 2 pi, cos dashed*, is written by the model. Such a Python program is run only when it does nothing but compute and draw, and is corrected once if it fails; such a MATLAB script is run in MATLAB in the background (about half a minute) to get its figure.

   Use **Open plot preview** in the workbench to view the PNG.
2. When the plot is ready, use the keypad **Copy** icon. It copies the plot together with the equation it was made from. Open the LaTeX menu and press **Paste**. The figure file is copied into `figures/`, and one fragment with the equation followed by the figure is added to the document through `\input`, with `graphicx` loaded if needed. A plot made from code gets a code listing instead of the equation, and a figure without either is inserted on its own. The LaTeX project is asked for once and remembered; change it with **Browse** on the version-control page.
3. For a more complex plot, generate it in MATLAB, VS Code, or PyCharm and export a PDF or PNG. Copy the file in Explorer and use **Paste** in the LaTeX menu. The same action accepts an image from the Windows clipboard. For code review, copy text in the editor, then use **Paste** in the ChatGPT menu to stage it.

Without the LogiInsight camera, the workbench uses the first ordinary webcam instead, such as a laptop's built-in camera, and says so in the status line. It runs the same capture worker, hand tracking, and writing session, at whatever resolution the camera delivers, so a demo on a laptop camera exercises the same code. Tilt the lid so the camera sees the paper, or hold the sheet up to it; writing that appears upside down is turned upright from the direction of your hand. To check a camera before a demo, run `uv run paper_camera_check.py` and write a few letters: it reports resolution, frame rate, whether your hand and pen grip are seen, how many pen-tip samples counted as pen-down, and the writing region it found.

The camera path uses 1080p MJPG via the LogiInsight SDK's OpenCV capture helper. The PC vision model reads the page from RGB frames. The camera's SFTP AI JSON provides face detections and landmarks. [Logitech camera SDK](https://raw.githubusercontent.com/Logitech/hackathons/master/docs/logiinsight/API.md)

## Overleaf

Overleaf has no interface on your computer, so PaperBridge pastes into it the way you would: with the clipboard and Ctrl+V.

1. Open your project in Overleaf and click in the editor where the LaTeX should go.
2. Make the equation or table with **Equation** or **Table**, or copy something with **Copy**.
3. Press **Overleaf**. The LaTeX (an `equation` environment, a booktabs table, a listing, or a paragraph, as **Paste** would make it) goes on the clipboard, the browser window with your Overleaf project comes to the front, and Ctrl+V is pressed there, so it lands at the cursor.

The keystroke is only sent when the window in front is a browser showing an Overleaf project. If none is open, or its tab is not the active one in its window, Overleaf's project list opens instead and the LaTeX waits on the clipboard: open the project, click where it should go, and press **Overleaf** again or Ctrl+V. A copied plot is pasted as its equation; upload the figure file in Overleaf yourself.

With nothing drafted or copied, **Overleaf** offers the earlier upload: the selected local project is packaged as a ZIP and Overleaf's dashboard opens; choose **New project → Existing project (.zip)**. [Overleaf project upload](https://docs.overleaf.com/managing-projects-and-files/uploading-a-project)

## ChatGPT image

On the ChatGPT page, press **Image**, draw, and press **Image** again or lift your hand. Press it twice quickly for a drawing that is already on the page: with the pen pointing at it, that drawing is taken. Nothing is read. The picture of the drawing is saved as `sketch.png`, put on the clipboard as an image, and ChatGPT opens in the browser; once its window is in front, the picture is pasted, the request to generate a finished image from the sketch is typed, and Enter sends it. If the picture is still uploading, press Enter yourself.

Keys are only pressed while ChatGPT is the window in front. Otherwise nothing is typed: the drawing stays on the clipboard, so click in ChatGPT's message box and press Ctrl+V; the request is in the draft panel. **Image** takes the place of **Photo** on this page; **Open photo** is still in the workbench window.

## LTspice

Open **LTspice** on page 1. Draw the circuit with a reference and value on every part (`V1 5`, `R1 1k`, `C1 100n`, `L1 1m`, `D1`, `I1 1m`), label the nets you care about (`in`, `out`), and draw a ground symbol or write `GND`. A sketch without them still gives a schematic you can run and edit: parts are numbered, missing values get defaults (1k, 100n, 1m, 5 V, 1 mA), the source's negative side becomes ground, and each assumption is listed in the notes and named in the status line. A written command such as `.tran 10m` or `.ac dec 20 1 1Meg` is used as the simulation command. Without one, PaperBridge picks `.tran 10m` for SINE or PULSE sources, an AC sweep for `AC` sources, and `.op` otherwise.

- **Schematic** captures the page, reads the parts and their nets, and opens the generated `.asc` in LTspice. Each part is placed on a grid with a net flag on both pins, so parts that share a label are connected. The schematic is valid for any topology, but it isn't laid out like your drawing; move parts and draw wires in LTspice if you want that. The netlist that was read is shown under the draft for checking, and the schematic is run once in LTspice's batch mode before it opens (about a second), so the notes say whether it simulates and what came out. If LTspice rejects it, the error goes back with the drawing for one corrected reading.
- **Simulate** runs the schematic in batch mode. On success the status line gives the result, such as `V(out) = 3.837 V` for an operating point or `V(out): -0.85 to 0.86 V` for a transient, and the schematic opens in LTspice with the simulation run, so you can probe waveforms. On failure it says what to check on the sketch first (two sources across the same nets, a value LTspice doesn't know, an incomplete command, a net without a path to ground), then LTspice's own message.
- **Paste** stages copied SPICE text as a `.cir` netlist. **Copy** takes the draft, for example to paste it into ChatGPT for review.

With the cloud setting Claude reads the drawing. The local 2B vision model, used otherwise, reads references, values, and commands well, and simple wiring usually. Check the netlist for larger circuits: a note warns when every part was read between the same two nets. A net that reaches only one part is read again once and flagged if it stays that way.

## Version control

Version control always acts on **the project you're working in**, so you never pick a folder first:

- From VS Code it's the folder of the VS Code window you used last. With several projects open, the one in front wins.
- From LaTeX it's the selected LaTeX project. From MATLAB, LTspice, and the other apps it's the folder of the file PaperBridge last opened there, and otherwise the front VS Code window.
- **Browse** picks another project folder by hand. That choice holds until you switch to a different app page. In LaTeX it also becomes the LaTeX project.

Each status message names the repository it used. There are two ways in: the **Version control** key on every app page, or the keypad's page buttons from any app. Page 2 is version control and page 3 holds the GitHub and GitLab actions, and both leave the app page as it is. Page 1 has no version-control tile: it appears once you're in an app.

| Page | Keys |
| --- | --- |
| Version control (also page 2) | Camera, Commit, Push / Pull, Branch, Diagram / Host, Browse, Back |
| Host (also page 3) | Camera, Issue, Request / Publish, Open, Repo / Paste, Back, Home |

- **Commit** opens a terminal in the repository. It lists the staged and the unstaged files and asks whether to stage everything: the default is yes when nothing is staged yet, and no when you staged files yourself. Then it asks for the message, commits, and offers to push. An empty message cancels.
- **Push** and **Pull** work on the current branch. Push never forces, and Pull only fast-forwards.
- **Branch**: write a short name such as *add login page*. It becomes `add-login-page` and is checked out.
- **Diagram** runs a drawn branch graph; see below.
- **Issue** and **Request**: write a title, and optionally a description under it. PaperBridge reads whether the remote is GitHub or GitLab (self-hosted too) and opens the issue, pull request, or merge request in your browser with everything filled in. You submit it there, so no access token is needed. Request pushes the branch first and targets the default branch.
- **Publish**, for a repository without a remote: the first press opens the new-repository page. Create it, copy its URL, and press **Publish** again to add it as `origin` and push.
- **Open** shows the repository page. **Repo** turns a written project idea into a new repository with a scaffold and an initial commit. **Paste** commits a copied note: text becomes the commit message, and a todo list is added to `TODO.md`.

### Draw a branch diagram

Press **Diagram** and draw the history you want. Draw each branch as a horizontal line with its name at the left. A fork starts a new branch and a join is a merge. Circle a node and write the message next to it for a commit. Circle a branch name to push it. Press **Diagram** again or lift your hand when done. The reader turns the drawing into one command per line, which you can check in **Read from paper**:

    branch feature/login from main
    commit feature/login "Add login form"
    merge feature/login into main
    push main
    tag v1.0 on main

PaperBridge shows the numbered plan in the draft panel and runs it right away; pressing the key is the confirmation. Steps run in order on the selected repository:

- A new branch is created from its parent with `git switch -c`. An unknown parent is first created from the branch you're on. Existing branches are reused.
- A commit takes your current changes, the staged ones if any. When nothing is left to commit, it makes an empty commit so the drawn history still appears, and the status line says so.
- A merge uses `git merge --no-ff`. On a conflict it's aborted, nothing changes, and the run stops there.
- A push uses the normal safe push. It's skipped with a note when the repository has no remote.

PaperBridge never forces, deletes branches, or rewrites history. It reports lines it couldn't read and returns to your original branch at the end.

## Plan

Open **Plan** on page 1 and press **Gantt**. Write your pipeline top to bottom while you brainstorm: one task per line with a duration (`2w`, `10d`, `1m`), an arrow when a task follows something other than the line above, and a star or the word *milestone* for milestones. Press **Gantt** again or lift your hand when done.

PaperBridge schedules the tasks from today, each after the one above unless an arrow says otherwise, and opens two results: the rendered chart (PNG and PDF) and a Markdown file with the same plan as a Mermaid `gantt` block, which VS Code and GitHub render. **Copy** takes the chart; **Paste** in LaTeX then inserts it as a figure. Lines that couldn't be read as a task or milestone are listed in the notes.

## Cloud or local

The **Cloud** box at the top right of the workbench chooses where reading and generation run. It is on by default and remembered as `"generation": "cloud"` or `"local"` in `%LOCALAPPDATA%\LogiInsightPaper\settings.json`.

- **Cloud** uses the Claude Code CLI (`claude`) with the account you are signed in to there; no API key is needed. Run `claude` once in a terminal to sign in. Each request counts toward that account's usage limit; when the limit is reached, or Claude doesn't answer within its time limit (25 s for a reading, 40 s for code, 60 to 90 s for a project or a circuit), the local models answer instead and the cloud is tried again a minute later.
- **Local** uses only the Ollama models below. Nothing leaves the computer.

What is sent to Claude: the picture of the writing (the cropped photo, and the ink picture of a recording), what the pressed key expects, your reading once you confirmed it, and the names from your project that the reader already uses as hints. Nothing else from your files is sent: no paths, no file contents, no folder or repository names. The CLI itself adds the e-mail address of the Claude account, the Windows version, and its working folder, which PaperBridge sets to the public profile folder so that it names neither you nor a project. It runs without tools, without your Claude settings and extensions, and without saving a session. The **Image** and **Open ChatGPT** keys send the drawing or the brief to ChatGPT through your browser, under your ChatGPT account.

The apps' own assistants can't do this job from outside the app. VS Code's `code chat` only opens the chat panel for you; MATLAB's assistant, where it is installed, works inside the MATLAB desktop only; LTspice has none; ChatGPT is reached through its web page (**Open ChatGPT**). **Open VS Code Chat** in the workbench still hands the reviewed reading to the chat in VS Code.

## Run the local models

Install Ollama if it is unavailable and pull the two models once.

    ollama pull glm-ocr:q8_0
    ollama pull qwen3-vl:2b-instruct

`glm-ocr` reads the handwriting; `qwen3-vl` reads drawings and writes code from pseudocode. Both run on this computer. The workbench also detects the portable installation used for testing under **%LOCALAPPDATA%\LogiInsightTools**. Without `glm-ocr`, the vision model reads everything, which works but takes several seconds per reading.

On a 4 GB graphics card the two models share the memory. PaperBridge keeps both loaded with small context windows, and gives the card to one model alone for the few requests that need more (a picture for the vision model, or a long project generation). Loading both takes a few seconds the first time; the camera start does it in the background.

## Check speed and accuracy

    uv run paper_bench.py --pipeline     # snapshot path per key: photo, ink, reading, check, result
    uv run paper_bench.py --live         # live path: simulated writing under a moving hand
    uv run paper_selftest.py             # cross-app flows on the real workbench, without a camera

`paper_bench.py` writes known text in handwriting fonts, places it on a page as a camera sees it (20 px letters, grey ballpoint ink, uneven light, noise, blur), and reports exact matches, character accuracy, and seconds. On the development laptop (RTX 3050, 4 GB) the snapshot path read 71 of 72 samples exactly and the live path 53 of 54, with a finished result about one second after the photo or the end of writing. These are fonts, not your handwriting: use the numbers to compare changes, and `paper_camera_check.py` to see what your own camera and pen give.

`paper_selftest.py` drives the real workbench through 20 steps with the real models, in the cloud or, with `--local`, on this computer: code from an equation, the check of a reading confirmed with the key, a plot program that is run, code from pseudocode that must compile, copy and paste into LaTeX, VS Code, MATLAB, and ChatGPT, a table, a dashed-oval copy, a Gantt chart, a project from a class sketch, a report skeleton, and a branch and a commit. It opens nothing on screen and works in a temporary folder.

## Configure the MX Keypad

For a new installation, use the .NET 10 SDK with Logi Options+ and Logi Plugin Service 6.4 or newer.

    uv sync --locked
    .\keypad-plugin\setup.ps1

`setup.ps1` builds the plugin and registers it. The keys and their icons are built into the plugin, so run it again after an update that adds a key, such as **Image** on the ChatGPT page. If the actions are missing, use the Options+ setting to restart Logi Plugin Service. In **All Applications**, the **PaperBridge** profile has three pages. Assign **LogiInsight Paper → Paper key 1–9** to page 1, **Paper key 10–18** to page 2, and **Paper key 19–27** to page 3, in order. Page 1 redraws itself: it shows the app icons (VS Code, MATLAB, LaTeX, ChatGPT, KiCad, LTspice, Plan), and pressing one shows that app's keys. It also follows your computer: when you bring VS Code, MATLAB, LTspice, ChatGPT, KiCad, a TeX editor, or an Overleaf or ChatGPT browser tab to the front, the keypad shows that app's page by itself. Options+ has its own profile for VS Code; `setup.ps1` does not touch it, so assign the same 27 paper keys there too, otherwise that profile shows its stock keys while VS Code is in front. **Home** returns to the apps. Pages 2 and 3 always show version control and its host actions. When the workbench is closed, page 1 still shows the apps, and pressing one starts the workbench on that app. New apps and keys come from `paper_menus.json`, so the profile never needs editing again.

If the keys stay blank after the plugin service was stopped by hand, run `setup.ps1` again: it clears the crash marker that makes the service skip the plugin.

Keys show only the symbol. The **Paper Apps** folder actions still exist, but Options+ decorates folder keys, so the nine paper keys are the cleaner setup. If a key shows its name or a cropped symbol, select the key in Options+, reset its icon, and turn off the title.

## Use both devices on a laptop with one USB-C port

Connect the LogiInsight camera directly to the laptop's USB-C port. Connect the MX Keypad to USB-A with a USB-A-to-USB-C **data cable**. If you need to share the USB-C port, use a powered SuperSpeed USB hub with downstream **data** ports. Reconnect both devices and check that Options+ sees the keypad and the RGB preview lists **LVNext Camera**.
